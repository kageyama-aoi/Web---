## 背景
`js/app.js` に初期化・イベント配線・ユースケース実行・自己テスト処理が集中しており、変更時の影響範囲が読み取りづらい。

## 現在の課題
- `app.js` が司令塔以上の責務を持ち、保守時の見通しが悪い
- DOM取得とイベント登録が密結合で、機能追加時の差分が大きくなりやすい
- 自己テスト処理が本体ロジックに混在し、主処理の可読性を下げている

## 目的
挙動を変えずに `app.js` の責務を分離し、可読性・保守性・テスト容易性を上げる。

## 受け入れ条件（Doneの定義）
- [ ] 既存のテストが全て通ること
- [ ] 挙動が変わっていないこと
- [ ] `app.js` の責務が「初期化オーケストレーション中心」に整理されていること
- [ ] DOM参照・イベント配線・自己テスト処理が分離され、各モジュールの役割が明確なこと

## タスクチェックリスト
- [ ] `app.js` の責務を分解し、DOM参照取得を専用モジュールへ分離
- [ ] イベントリスナー登録を専用モジュールへ分離
- [ ] 自己テスト処理を専用モジュールへ分離し、既存UI導線（`#selfTest`）を維持
