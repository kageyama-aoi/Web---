WSL2 環境構築まとめ & トラブルシュート集

ここまでの学習と実際のエラー体験を整理した資料です。今後の開発環境構築のベースや、再発時の参考にできます。

1. 基本の整理

npm / Node.js

  • npm install は依存関係をインストールするコマンド。
  • WSL は Windows と別環境。Node/npm は WSL 内に入れ直す必要あり。
  • fnm（Fast Node Manager）を使うと複数バージョン管理が容易。
# LTS版Node.jsを導入
fnm install --lts
fnm use --lts
node -v
npm -v

Git

  • Git も WSL 側にインストールして利用する。
  • SSHキーは WSL 側で生成し、GitHubに登録するのが安全。

Docker

  • エンジンは Windows の Docker Desktop。
  • WSL から docker / docker compose で操作。
  • プロジェクトは /home/<user> に置いた方が高速。

WSL ユーザー管理

  • 普段は一般ユーザー＋sudo で作業するのが安全。
  • rootで起動：wsl -d Ubuntu -u root
  • デフォルト設定：wsl --set-default Ubuntu

2. トラブルシュート集

Docker エンジン接続エラー

unable to get image 'postgres:15.1' ... dockerDesktopLinuxEngine not found

→ Docker Desktop を起動し、WSL Integration をONにして docker context use desktop-linux

fnm インストール時の依存不足

Not installing fnm due to missing dependencies (unzip)

→ sudo apt install unzip で解決

sudo 実行時にパスワード要求

sudo: a password is required

→ rootでログインして passwd <ユーザー> で再設定

GitHub CLI が認識されない

'gh' is not recognized as a command

→ Windowsは winget install --id GitHub.cli、WSLは sudo apt install gh

docker-compose.yml の警告

the attribute `version` is obsolete

→ YAMLから version: 行を削除

3. チェックリスト

  • WSL内で node -v, npm -v, git --version, docker version が通るか？
  • Docker Desktop が "Engine running" か？
  • プロジェクトは /home/<user> に置かれているか？
  • SSHキーは WSL 内で作って GitHub に登録したか？
