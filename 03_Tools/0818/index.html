③ 使い方ガイド（困ったらここから）

📌 クイックスタート
  1. 「サンプルAPI」を選ぶ（Frankfurter等）。
  2. 必要ならクエリパラメータを追加。
  3. ▶ 送信を押し、右の「結果」パネルでStatus等を確認。
  4. タブで JSON / Raw / Headers 等を切替え、差分で学ぶ。
  5. cURLをコピーして、CLIでも再現。
🧪 ハンズオン課題（5分ドリル）
  1. メソッドの差：JSONPlaceholder をPOSTに切替え、Bodyを入れて返り値の違いを観察。
  2. エラー観察：URLをわざと間違える→Status とエラーを読む。
  3. CORS: WorldTimeAPI を叩き、コンソールのCORSエラーを確認 → cURLで成功させる。
🛠 よくある詰まり & トラブルシュート
  • CORSでブロック：ブラウザから直接叩けないAPIは普通にあります。
    対処：① サーバ側で Access-Control-Allow-Origin を許可、② 学習目的なら 同一オリジンの簡易プロキシを挟む。
  • JSONが壊れる：ボディに末尾カンマ/単一引用符。→ JSON.stringify を通す、または エディタでJSON整形。
  • 401/403：キーやトークン未設定。→ Authorization ヘッダ、もしくは ?apikey= を確認。

④ OAuth 2.0（PKCE）実演

PKCE 認可コードフロー（学習用）

※ Authorization / Token エンドポイントと client_id を入力。CORS で失敗する場合は下の PowerShell / cmd の cURL を使ってください。
OAuth Status: —

トークン交換（学習用サンプル）

# PowerShell（Windows）推奨: curl.exe を明示
# 認可成功後、{AUTH_CODE} を置き換えて実行
$code = '{AUTH_CODE}'
$verifier = '{CODE_VERIFIER}'
$token = '{TOKEN_ENDPOINT}'
$client = '{CLIENT_ID}'
$redir = '{REDIRECT_URI}'
$body = "grant_type=authorization_code&code=$code&client_id=$client&redirect_uri=$redir&code_verifier=$verifier"
curl.exe -s -X POST -H "Content-Type: application/x-www-form-urlencoded" --data $body "$token"
REM cmd.exe 用（ダブルクォートとバックスラッシュで値をエスケープ）
set CODE={AUTH_CODE}
set VERIFIER={CODE_VERIFIER}
set TOKEN={TOKEN_ENDPOINT}
set CLIENT={CLIENT_ID}
set REDIR={REDIRECT_URI}
curl -s -X POST -H "Content-Type: application/x-www-form-urlencoded" --data "grant_type=authorization_code&code=%CODE%&client_id=%CLIENT%&redirect_uri=%REDIR%&code_verifier=%VERIFIER%" "%TOKEN%"
