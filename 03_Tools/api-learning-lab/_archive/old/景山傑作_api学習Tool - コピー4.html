③ 使い方ガイド（困ったらここから）

📌 クイックスタート
  1. 左の「サンプルAPI」を選ぶ（まずは Frankfurter（為替））。
  2. 必要なら クエリパラメータを追加（例: from=USD, to=JPY）。
  3. ▶ 送信を押す → 右パネルで Status / Time / Size / Type を確認。
  4. タブで JSON / Raw / Headers / Request を切替え、差分で学ぶ。
  5. cURLをコピー（Shift+Enter）して、CLIでも再現。
🧪 ハンズオン課題（5分ドリル）
  1. HTTPメソッドの差：JSONPlaceholder を GET→POSTに切替え、Bodyに{"title":"x"}を入れて返り値の違いを観察。
  2. クエリの影響：Open-Meteo の latitude/longitude を東京→大阪に変え、値の差とレスポンスサイズを比較。
  3. Content-Type：Content-Type を外して送信→サーバが受理するか？ヘッダを戻すと何が変わるか。
  4. エラー観察：URLをわざと間違える→Status と JSONパネルのエラー を読む。
  5. 中断の学習：重いAPIを投げた直後に■ 中止→AbortError を確認。
🛠 よくある詰まり & トラブルシュート
  • CORSでブロック：ブラウザから直接叩けないAPIは普通にあります。
    対処：① サーバ側で Access-Control-Allow-Origin を許可、② 学習目的なら 同一オリジンの簡易プロキシを挟む（下記サンプル）。
  • JSONが壊れる：ボディに末尾カンマ/単一引用符。→ JSON.stringify を通す、または エディタでJSON整形。
  • 401/403：キーやトークン未設定。→ Authorization ヘッダ、もしくは ?apikey= を確認。
  • 429（レート制限）：一定回数でブロック。→ レスポンスヘッダの Retry-After を読んで待つ／指数バックオフ。
  • 400/422（バリデーション）：クエリ名のスペル・型（文字列/数値/配列）見直し。

※ 本ツールは学習用。業務利用では秘密情報（APIキー等）をフロントに直接置かないでください（下記セキュリティ参照）。

🔒 セキュリティ & APIキーの扱い
  • 原則：キーはサーバ側で保持。フロントからは自前API（サーバ）にリクエスト→サーバから外部API。
  • 学習時にキーを試すなら：.env で管理＋ローカル開発 or 一時的な 無料枠 キー。
  • 公開時：参照専用キー/スコープ制限・レート制限・ドメイン制限を設定。
🌐 簡易プロキシ例（CORS回避／キー隠し） 
// Cloudflare Workers（学習用最小）
export default {
  async fetch(req) {
    const u = new URL(req.url);
    const target = u.searchParams.get('url');
    if(!target) return new Response('missing url', {status:400});
    const r = await fetch(target, { headers: { 'Authorization': 'Bearer YOUR_API_KEY' }});
    return new Response(r.body, { headers: { 'content-type': r.headers.get('content-type') || 'application/json', 'Access-Control-Allow-Origin': '*' }});
  }
}
// 使い方: https://your-worker.workers.dev/?url=https%3A%2F%2Fapi.example.com%2Fv1%2Fdata

※ 実運用では 許可リスト・署名・監査ログ を必ず入れてください。

🧭 観察ポイント（プロの視点）
  • 安定性：Status／Time のブレ。失敗時の エラーメッセージの質。
  • コスト：レスポンス Size の削減（不要フィールドは fields= で限定）。
  • 互換性：content-type の違い（application/json / text/plain / image/*）。
  • 再現性：cURL 比較、保存した クエリ・ヘッダ の再利用。
📚 さらに学ぶ：RESTの基本とリクエスト設計
  1. リソース指向：URLは「名詞」、操作はHTTPメソッド（GET/POST/PUT/PATCH/DELETE）。
  2. クエリ設計：limit/offset/sort/fields で最小限のデータ取得。
  3. エラー設計：機械可読な code/message/details を返すAPIは使いやすい。
📝 宿題（実務寄り）
  1. 為替＋祝日APIを組み合わせ：営業日のレート一覧を取得（JPの祝日を除外）。
  2. 位置情報APIで店舗間距離マトリクスを作成し、最短移動順を仮設計。
  3. レート制限を再現：429 を受けたら Retry-After を読みリトライ。

④ OAuth 2.0（PKCE）実演 & Windows向け cURL

PKCE 認可コードフロー（学習用）

※ Authorization / Token エンドポイントと client_id を入力。CORS で失敗する場合は下の PowerShell / cmd の cURL を使ってください。
OAuth Status: —

トークン交換（学習用サンプル）

# PowerShell（Windows）推奨: curl.exe を明示
# 認可成功後、{AUTH_CODE} を置き換えて実行
$code = '{AUTH_CODE}'
$verifier = '{CODE_VERIFIER}'
$token = '{TOKEN_ENDPOINT}'
$client = '{CLIENT_ID}'
$redir = '{REDIRECT_URI}'
$body = "grant_type=authorization_code&code=$code&client_id=$client&redirect_uri=$redir&code_verifier=$verifier"
curl.exe -s -X POST -H "Content-Type: application/x-www-form-urlencoded" --data $body "$token"
REM cmd.exe 用（ダブルクォートとバックスラッシュで値をエスケープ）
set CODE={AUTH_CODE}
set VERIFIER={CODE_VERIFIER}
set TOKEN={TOKEN_ENDPOINT}
set CLIENT={CLIENT_ID}
set REDIR={REDIRECT_URI}
curl -s -X POST -H "Content-Type: application/x-www-form-urlencoded" --data "grant_type=authorization_code&code=%CODE%&client_id=%CLIENT%&redirect_uri=%REDIR%&code_verifier=%VERIFIER%" "%TOKEN%"
