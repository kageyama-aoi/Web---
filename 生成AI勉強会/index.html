AI初心者向け勉強会

対象：AIの扱い方がまだ分からない方向け／所要：90分想定／目的：AIを「怖い未知」から「頼れる相棒」に

1. 勉強会の全体構成（90分）

タイムライン

時間内容狙い
10分オープニング＆アイスブレイク安心感・ゴール共有

20分ワークショップ自分事化・定着
10分まとめ・次の一歩行動宣言

ゴール

  • AIへの質問の型（目的＋条件＋形式）を掴む
  • スプシ関数・調べものを実務で即試せる状態

2. 導入（アイスブレイク台本）

進行みなさん、こんにちは！集まってくれてありがとうございます！

進行今日はAIについて、一緒に見ていきましょう。リラックスして聞いてくださいね。

進行さっそくですが、皆さんは『AI』って聞くと、どんなイメージがありますか？良いことでも悪いことでも、何でもOKです。ちょっと時間をとるので、チャットに気軽に書き込んでみてください。

（ここで30秒～1分ほど待つ。参加者の書き込みをいくつか拾って読み上げる）

進行ありがとうございます！ 『仕事が速くなりそう』って期待もあれば、『難しそう』『仕事がなくなるかも…』みたいな不安の声もありますね。うんうん、色々なイメージがあると思います。

進行今日の目的は、まさにその漠然としたイメージを、『明日から使える具体的な道具』に変えることです。そのために、今日は4つのステップで進めます。

  1. まず、AIとの上手な付き合い方を、職場のあるあるな会話劇で見ていきます。（→ 3. 会話劇）
  2. 次に、誰でも真似できるプロンプトの基本の型を学びます。（→ 4. プロンプトの工夫）
  3. そして、AIの回答を自分好みに変えていく「育て方」のコツを紹介します。（→ 5. プロンプトを育てる）
  4. 最後に、AIを思考のパートナーにするための応用的な聞き方も見ていきます。（→ 6. 応用プロンプト）

進行この4つを押さえれば、AIは「よく分からない何か」から「頼れる相棒」に変わります。さっそく一緒に見ていきましょう！

登場人物

4. プロンプトの工夫（入口体験：整理型／会話型）

1A. 会話型（先生と生徒のやりとり）

“目的とか書くのめんどくさい派”はこちら。会話で進めて理解する。

あなたは先生役、私は生徒役として会話形式で説明してください。  
テーマは「Googleスプレッドシートで日付から曜日を表示する方法」です。  

ポイント：  
- 会話は短すぎず、理解を深められるやり取りにしてください。  
- 生徒が疑問を挟み、先生が丁寧に答える流れにしてください。  
- 数式の例（=TEXT(A1,"aaa") など）を会話の中で出してください。  
- 最後には「なるほど！こうすれば曜日が出せるんですね」と生徒が理解する形で締めてください。  

助成金について説明してください。
社会人向けに、3分で読める要点だけ。表形式で「制度名／対象／金額／URL」を整理してください。

※ 会話型で理解 → 必要に応じて整理型に「転記」すると再利用が楽。

1B. 整理型（目的・条件・形式で書く）

しっかり言語化してから依頼したい人向け。後で資料にも残しやすい。

# 目的
◯◯をしたい  

# 対象
中学生向け／社会人向け／初心者向け

# 形式
会話形式／表形式／箇条書き  

# 条件
例を3つ／公式URLを添えて／よくある注意点も
具体例プロンプトを見る 
# 目的
スプレッドシートである関数を作って縦方向に貼り付けるのめんどくさい
もっと楽に対応できる関数とかないのか知りたい

# 対象
初心者向け

# 形式
会話形式  

# 条件
よくある注意点もおりまぜて

# 具体例
会話式の場合
生徒：「先生、スプレッドシートで日付から曜日を出したいんでござるが、どうしたらいいナリ？」
先生：「いい質問ですね。まずは、TEXT関数を使う方法があります。例えばセルA1に日付が入っているとします。その場合、=TEXT(A1,"aaa") と入力すると…何が出ると思いますか？」
生徒：「うむ、、、“aaa”って何ナリ？」
先生：「これは書式コードといって、aaaは“曜日の略称”を意味します。だから、月とか火が表示されるんです。さっきからその口調なんなの？」
例（スプシ関数）：
目的日付から曜日を日本語の短縮形で表示したい
形式ステップ→関数→注意点（箇条書き）
質問Googleスプレッドシートで、A1の日付の曜日を日本語の短縮形で表示する関数と注意点を、ステップ＋関数例＋よくあるミスの順で教えて。

1C. クイズ生成型（理解度チェック）

学んだ知識が定着したか確認したいときに便利。AIに問題と解答を作ってもらいます。

Googleスプレッドシートの関数理解を確認したいので、
さきほどあなたに質問した内容で初心者向けに徐々に難易度が上がる問題を3つ作ってください。
回答は必ず別枠で示してください。
AIの回答例：

問1（初級）：セルA1からA5までの合計値を計算する関数は何でしょう？

回答を見る
=SUM(A1:A5)

問2（中級）：セルB列の中で「完了」という文字が含まれるセルの数を数える関数は何でしょう？

回答を見る
=COUNTIF(B:B, "完了")

問3（応用）：セルC1の日付データ（例: 2024/8/20）から、「火曜日」のように日本語の曜日を正式名称で表示する関数は何でしょう？

回答を見る
=TEXT(C1, "dddd")

整理型 vs 会話型（対応表）

スタイル特徴向いている人例プロンプト
整理型 目的・条件を表で整理／後から再利用しやすい 業務に残す・反復利用したい 「【目的】◯◯ 【条件】◯◯ 【形式】◯◯」
会話型 対話で自然に理解／気楽に始められる 最初の学習・文章化が苦手 「先生役と生徒役で説明して」
おすすめ進行：まず全員で会話型を体験 → 整理型へ写経して“型”を掴む。
5. プロンプトを育てる（回答精度を上げるには）

一度で完璧な答えを求めず、対話を通じてAIの回答を「育てる」という意識が重要です。精度を上げるための4つのテクニックを紹介します。

① フィードバックと制約追加

回答がズレていたら、遠慮なく指摘・修正させます。制約を追加して出力を絞り込むのも有効です。

(AIの回答に対して...)

- その解釈は違います。◯◯という観点で修正してください。
- もっと具体的に。専門用語を使わずに説明してください。
- 回答は3つのポイントに絞り、箇条書きでお願いします。
AIは人間と違って感情がないので、何度でも遠慮なく「やり直し」を命じることができます。

② お手本提示 (Few-shot)

AIに「お手本」をいくつか見せることで、期待する回答の形式や文体を具体的に教え込むテクニックです。

以下のテキストを、指定のフォーマットに変換してください。

# お手本
入力: りんご, 150円, 産地：青森
出力: ・りんご（青森産） - 150円

# 本題
入力: みかん, 120円, 産地：愛媛
出力:
単に「フォーマットして」と指示するより、具体的な「入力→出力」の例を1つか2つ見せるだけで、AIはルールを推測し、複雑な形式でも正確に再現してくれます。
応用例：SQL整形アシスタント

整形ルールと入出力例を具体的に示すことで、自分好みのコーディングスタイルをAIに学習させることができます。

あなたはSQL整形アシスタントです。以下のルールでSQLを整形してください。

【出力ルール】
- 出力はSQLのみ（前後の説明文なし）
- インデントは例に従う事 
- 例の「コメントの付け方・位置・粒度」を踏襲する
- 末尾にセミコロンを付ける

【入力例と整形例】
入力例:
select id, name from users where age > 20 order by name;

整形例:
-- ユーザのIDと名前を取得 
SELECT
    users.id,   -- ユーザID
    users.name -- ユーザ名
FROM
    users
WHERE
    users.age > 20;


【整形対象SQL】
select id, name, branch_name from account join branch b on branch_id = branch_id where city='Tokyo' order by name;

③ 思考プロセスの要求 (CoT)

複雑な問題や計算を依頼するとき、結論だけを求めずに思考の過程を説明させると、間違いが減ります。

以下の問題について、ステップ・バイ・ステップで考えて、最終的な結論を導き出してください。

# 問題
(ここに複雑な問題や計算)

# 回答形式
1. 問題の分析: ...
2. 計算過程: ...
3. 結論: ...
「Chain of Thought (思考の連鎖)」と呼ばれるテクニックです。

④ 役割の再確認と深掘り

会話が長くなるとAIが当初の役割を忘れることがあります。役割を再確認させたり、より深く掘り下げさせましょう。

(会話の途中で...)

あなたは引き続き[役割]です。その視点を忘れずに、先ほどの回答について以下の点を深掘りしてください。

- なぜその方法が最適だと考えますか？
- 他に考えられるリスクはありませんか？
「なぜ？」を繰り返すことで、表面的な回答から本質的な洞察を引き出せます。
6. 応用プロンプト（思考の壁打ち相手にする）

基本の型に慣れたら、AIを「思考のパートナー」にするための応用的な聞き方を試してみましょう。

応用1：ペルソナ設定（役割を与える）

AIに専門家の役割を与えることで、回答の視点や質をコントロールします。

あなたは[役割]です。
[役割]の視点から、以下のテーマについて[形式]で説明してください。

# 役割の例
- プロのマーケター
- 経験豊富な人事担当者
- 顧客サポートのリーダー
- 厳しい品質管理者

# テーマ
(ここに相談したい内容)
例：「あなたはプロの編集者です。以下の文章を、中学生でも理解できるように、より簡潔で魅力的な表現に修正してください。」

応用2：多角的思考（視点を増やす）

一つの物事を複数の視点から検討させ、思考の漏れを防ぎます。

以下の提案について、3つの異なる視点から意見をください。

1. 賛成の立場（メリット）
2. 反対の立場（デメリットやリスク）
3. 長期的な視点（3年後の影響）

# 提案
(ここに検討したいアイデア)
これにより、自分一人では気づきにくい論点や懸念点を洗い出すことができます。

応用3：思考の深掘り（なぜ？を繰り返す）

表面的な答えで終わらせず、根本的な原因や目的を掘り下げさせます。

(AIの回答に対して...)

その回答の背景にある最も重要な理由は何ですか？
なぜそれが重要だと考えますか？
そのアプローチを取らなかった場合、どのような代替案が考えられますか？
トヨタ式の「なぜなぜ5回」のように、AIとの対話で本質に迫ります。

応用4：メタ認知（質問を改善させる）

自分の質問自体をAIに評価させ、より良い聞き方を発見します。（会話劇でも登場したテクニックです）

「(ここに自分の質問)」

上記は、私が本当に知りたいことを引き出すための最適な質問でしょうか？
もし改善できる点があれば、より効果的な質問の仕方を3パターン提案してください。
「どう聞けばいいか分からない」という悩みそのものを解決する強力な方法です。
7. 開発者向け 実践サンプル集

AIを「思考の壁打ち相手」から「コーディングの副操縦士」へ。システム開発の各工程で役立つ、より専門的な6つの活用サンプルを紹介します。

テストケースを網羅的に生成

仕様やコードを元に、正常系・異常系・境界値を含むテストケースを自動生成。テスト設計の工数を削減し、品質を向上させます。

以下の仕様を持つJavaScript関数 `calculatePrice(age)` のテストケースを、Jest形式で5つ生成してください。

# 仕様
- 6歳未満は無料
- 6歳以上18歳未満は500円
- 18歳以上は1000円
- ageが数値でない、または負数の場合は例外を投げる

# 条件
- 正常系、異常系、境界値を必ず含めること。
ポイント：仕様を明確に箇条書きで伝えることで、AIはテストの意図を正確に汲み取ります。

複雑な正規表現を瞬時に作成

「こういう文字列を抽出したい」という曖昧な要望から、複雑な正規表現を生成させ、さらにその意味を解説させることができます。

日本の携帯電話番号（`090-1234-5678` や `08012345678` など、ハイフンの有無両方）にマッチする正規表現を生成してください。

また、生成した正規表現の各部分が何を意味するのか、初心者にも分かるように解説してください。
ポイント：「解説も一緒に」と頼むことで、ブラックボックス化を防ぎ、学習にも繋がります。

API仕様書(OpenAPI)の雛形作成

APIの概要を伝えるだけで、OpenAPI (Swagger) 形式のYAMLやJSONの雛形を生成。面倒なドキュメント作成の初動を高速化します。

ユーザー管理（CRUD）のためのREST API仕様を、OpenAPI 3.0形式のYAMLで記述してください。

# エンドポイント
- `GET /users`: ユーザー一覧取得
- `POST /users`: 新規ユーザー作成
- `GET /users/{id}`: 特定ユーザー取得
- `PUT /users/{id}`: ユーザー情報更新

# Userモデル
- id (integer)
- name (string)
- email (string)
ポイント：エンティティの構造とエンドポイントを明確に指定するのがコツです。

コードのリファクタリング提案

既存のコードを貼り付け、より可読性や保守性の高いコードへの改善案を理由付きで提案させます。セルフコードレビューに最適です。

以下のJavaScriptコードは動作しますが、ネストが深くなっています。
`async/await` を使って、より可読性の高いコードにリファクタリングしてください。
