私なりのバイブコーディング・ロードマップ

「作って出す」を最速で回すための4週間（ゆっくり8週間）プラン。10本の小アプリ → 即公開 → ちょい改善。

全体像（ゴールとやり方）

  • ゴール：10個のミニWebアプリを「30〜60分スプリント」で作成 → 即公開 → 小さく改善。
  • 公開先：静的＝GitHub Pages ／ 動的＝Heroku / Render / Railway
  • 学び方：各アプリで毎回1テーマだけ意識（タイマー / API / Canvas / localStorage / 認証 など）
  • 成果物：GitHubリポ10個 + 公開URL10本 + 学びメモ（Notion）
Point. 迷ったら「まず動かす・まず出す」。完成度より回転数を大事にする。

あなたの5ステップ

1) 30分Webアプリ×10で深掘り 最優先

参考：イケハヤ：30分でできるWebアプリ10選

  • Todoリスト（localStorage）
  • ポモドーロ（setInterval・音）
  • 為替レート計算（外部API・async/await）
  • お絵かき（Canvas・タッチ）
  • パスワード生成（乱数・正規表現・Clipboard）
  • BMI計算（フォーム・可視化）
  • カウントダウン（日時計算）
  • QRコード生成（外部ライブラリ）
  • じゃんけん（ゲームロジック）
  • Markdownエディタ（パーサ・リアルタイム）

毎回：①機能は3点まで → ②AIで最小実装 → ③動いたら即コミット＆公開 → ④学び1行メモ

2) GitHub Pagesに即公開

静的で動くものはすべてPagesへ。GitHub Pages

  1. 新規リポに index.html を置く
  2. Settings → Pages → Deploy from a branch
  3. URL：https://<user>.github.io/<repo>/

以後は git push で自動公開。スマホ表示も都度確認。

3) 動的アプリ開発と公開

ローカル開発：Dockerで環境を構築。
PHP, MySQL, phpMyAdminのコンテナを用意し、本番に近い状態で開発を進めます。

  • Todoリスト（PHP+MySQLでデータ永続化）
  • Markdownエディタ（DBに保存・読込）
  • 為替レート（APIキーをサーバー側で管理）

本番公開：月額運用費を抑えるためVPSを契約。
自分でサーバーを構築し、作成した動的アプリケーションをデプロイします。

VPS候補：ConoHa VPS, Xserver VPS, さくらのVPS

4) 無料動画を2本だけ観る

概念→具体例の順で理解を加速。

  • バイブコーディング徹底解説（導入）
  • Sanity × バイブで運用例（実践）

YouTube「イケハヤ大学2.0」内に公開動画あり。

5) サロン入会（任意）

入門資料 → 事例探索 → 週1でURL共有＆軽レビューを習慣化。

まずは無料領域で回し、必要なら参加でもOK。

週ごとの進め方（4週間版）

Week 0（初回セットアップ／1日）

  • GitHubアカウント＆Pages確認、テンプレリポ作成
  • PaaSアカウント作成（Heroku / Render / Railway）

Week 1：静的5本を一気に

  • Todo
  • ポモドーロ
  • パスワード生成
  • じゃんけん
  • QR生成

学びタグ：setInterval / localStorage / Clipboard / ランダム / 外部ライブラリ

Week 2：静的5本 + UI磨き

  • 為替
  • Canvasお絵かき
  • BMI
  • カウントダウン
  • Markdownエディタ

1本はスマホ表示を重点改善（ヘッダ固定・タップ領域拡大など）。

Week 3：動的化チャレンジ

  • Todo API化（POST/GET/DELETE）→ デプロイ
  • Markdown保存API → デプロイ
  • 為替プロキシAPI（envでAPIキー管理） → デプロイ

Week 4：仕上げと発信

  • スクショ＆公開URLの作品ギャラリー作成
  • 気に入った2本を小改良（ダークモード / PWA など）
  • Xで #バイブコーディング 発信
ゆっくり派は各Weekを2週間に延長（全8週間）で無理なく。

デプロイ手順ミニメモ

GitHub Pages（静的サイト）

  1. index.html をコミット
  2. Settings → Pages → Deploy from a branch
  3. 数分後に公開：https://<user>.github.io/<repo>/

以後は git push で自動更新。手軽さNo.1。

VPS（手動インストール）

  1. VPS契約後、SSHでサーバーにログイン。
  2. Nginx, PHP, MySQL等をインストール。
  3. GitHubからアプリを git clone。
  4. DB接続情報などを設定し、公開。

サーバー構築の基礎知識が身につく。

VPS（Dockerデプロイ）

  1. VPS契約後、Dockerをインストール。
  2. 本番用のdocker-compose.ymlを用意。
  3. GitHubからアプリをgit clone。
  4. docker compose up -dで起動・公開。

環境の再現性が高く、管理が楽になる。

毎回使えるAIプロンプト雛形

以下の機能だけを満たす最小のWebアプリを1ファイルで作ってください。
条件：
1) スマホで見やすい　2) 日本語UI　3) コメント多め　4) 依存はCDN読み込み
5) GitHub Pagesでそのまま動作

機能：{ここに3点だけ書く}

まずは完成コードを提示 → その後に「改善の余地」を10個提案してください。

この設計にした理由

  • 回転数重視：完成度より「作って出す」頻度を上げると学習効率が高い
  • コスト最小で実運用体験：静的はPages、動的はFree/低額PaaSで十分
  • 1アプリ=1テーマで知識が定着、疲れにくい
