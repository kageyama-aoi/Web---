【事例報告】PHPMailer旧版によるDKIM不一致とエンコード差異

対象: 顧客「VK」/ 送信先: yahoo.co.jp / 送信元: vis-school-info@vis-kobe.co.jp
SPF/DMARC
ともに正常（顧客・弊社で確認済）
DKIM
顧客側でエラー検知（yahoo.co.jp）
本文エンコード差異
quoted-printable vs 8bit

1. 概要

管理画面から vis-school-info@vis-kobe.co.jp を差出人にして送信したメールについて、顧客「VK」から Yahoo! 宛で DKIM エラーの報告がありました。弊社・顧客双方のテスト送信ファイルを比較したところ、本文の Content-Transfer-Encoding が不一致（顧客: quoted-printable、弊社: 8bit）でした。

結論: 使用していた PHPMailer が非常に古い（v1.72 / 2004年）ため、エンコード処理と DKIM 署名の整合性に問題が生じた可能性が高い。
暫定対処として アプリ側からエンコードを 8bit に固定し、事象は解消。恒久対策としては PHPMailer 6.x への更新が必要。

2. タイムライン / 影響範囲

  • 顧客から DKIM エラー連絡（宛先: yahoo.co.jp）
  • 送信ファイル比較 → Content-Transfer-Encoding の差異を特定
  • 暫定対応：エンコードを 8bit 指定（TR95495）
  • 結果：DKIM エラー解消を確認

影響は Yahoo! 宛てで主に顕在化。DKIM は改行・空白・エンコード差でも検証が失敗し得ます。

3. 技術的背景と原因分析

3-1. DKIM とエンコードの関係

DKIM は「署名時に計算した本文（Body）のハッシュ」が、受信側で復元した本文ハッシュと一致するかを検証します。quoted-printable と 8bit で改行やエスケープが異なると、復元結果がズレ、検証失敗の引き金になります。

3-2. 古い PHPMailer の問題

  • v1.72（2004年）は DKIM 未実装期 のコードで、MIME/エンコードの扱いも旧式。
  • 本文やヘッダのエンコード/改行規則が現行サーバ運用と齟齬を起こすことがある。
  • 結果として DKIM canonicalization と整合しない出力になり、検証が失敗しやすい。

5. 対応方針

5-1. 暫定（実施済）

  • アプリから $mail->Encoding = '8bit'; を指定（TR95495）。
  • Yahoo! 宛てで DKIM エラー解消を確認。

5-2. 恒久

  • PHPMailer を 6.x 最新へ更新（Composer 管理推奨）。
  • DKIM はライブラリのネイティブ設定を使用（DKIM_domain, DKIM_selector, DKIM_private など）。
  • 送信ログ（ヘッダ含む）を保管し、検証失敗時に差分比較できる体制を整備。

6. DKIM 設定チェックリスト（受信側検証と整合させるために）

  • DNS: selector._domainkey.vis-kobe.co.jp に公開鍵（TXT）を正しく設定
  • 署名対象: From: を含むヘッダの選定（h=）と本文の canonicalization（c=relaxed/relaxed 等）
  • 送信時: 本文エンコードと改行（\r\n）の一貫性
  • 運用: 署名後に MTA/ゲートウェイでヘッダを書き換えない
  • 検証: 受信ヘッダの Authentication-Results で dkim=pass を確認

7. 用語の整理（誤解を避ける表現）

  • 原因表現：「PHPMailer 旧版の仕様に起因するエンコード不整合」
  • 暫定対処：「アプリからエンコード固定を追加（ワークアラウンド）」
  • 恒久対策：「PHPMailer 6.x 化および DKIM 署名の標準設定に移行」

8. 参考コード（PHPMailer 6.x での DKIM 設定例）

// Composer で導入済みを想定
use PHPMailer\PHPMailer\PHPMailer;
require 'vendor/autoload.php';

$mail = new PHPMailer(true);
$mail->CharSet = 'UTF-8';
$mail->isSMTP();
$mail->Host = 'smtp.example.com';
$mail->SMTPAuth = true;
$mail->Username = 'user@example.com';
$mail->Password = 'app-password-or-oauth';
$mail->SMTPSecure = 'tls'; // 465なら'ssl'
$mail->Port = 587;

// DKIM
$mail->DKIM_domain   = 'vis-kobe.co.jp';
$mail->DKIM_selector = 'selector1';           // 例
$mail->DKIM_private  = '/path/to/private.key';
$mail->DKIM_identity = $mail->From;

// 本文エンコード（必要時のみ明示）
$mail->Encoding = '8bit'; // 既定で問題なければ省略

$mail->setFrom('vis-school-info@vis-kobe.co.jp', 'VIS School');
$mail->addAddress('to@yahoo.co.jp');
$mail->isHTML(true);
$mail->Subject = 'テスト';
$mail->Body    = 'DKIMテスト本文';
$mail->send();

9. まとめ（要点）

  • 事象はライブラリの旧版仕様が引き金。アプリ修正は「回避策の実装」に過ぎない。
  • 暫定対処の 8bit 指定で解消したが、恒久的には 6.x 化が必須。
  • DKIM はエンコード・改行・ヘッダ整形の差で簡単に fail するため、署名直後の内容を変えない運用が重要。
